# 本地训练工作台使用说明

版本 0.3.0，2026-11-06。Windows x64 电脑端已生成可运行程序，不需要云服务器。

## 现在就能打开

在项目根目录双击 `启动电脑工作台.cmd`。程序实际位于 `.local/desktop/AI Motion-win32-x64/AI-Motion.exe`。

保留整个 `AI Motion-win32-x64` 文件夹；不能只拷贝 exe。当前为未做代码签名的内部便携测试版，不是安装器，不注册自动启动。

第一次打开没有虚构的训练记录。进入“今日计划 → 编辑第一份计划”，调整模板并保存，再点击“模拟运行计划”。

## 可用功能

| 页面 | 可操作内容 |
| --- | --- |
| 今日计划 | 显示今天安排、实际输入的本周时长、最近记录；使用模板创建计划 |
| 计划编辑 | 新建、保存、删除、另存副本；安排日期；动作增删、上下排序；设置组数、次数、训练与休息秒数 |
| 正在训练 | 运行模拟计划，顺序切换动作 / 组 / 休息；暂停、继续、结束并保存；显示手机同步来的统计 |
| 训练记录 | 来源筛选、查看详情、JSON 备份导出 / 合并导入 |
| 教练与分析 | 查看本地证据说明；配置接口、保存或清除密钥、测试连接；主动发送摘要并保存 AI 复盘 |
| 设备与设置 | 启停局域网接收、二维码 / 配对链接、选择电脑网卡、设备状态、体重和本地数据位置 |

模拟模式的次数来自计划节奏或手机游戏命中，不是人体动作识别。模拟记录不计入实际运动进度，不估算热量。电脑休眠会暂停模拟训练；关闭程序后阶段记录保留，当前不恢复未完成的模拟运行。

## 手机连接：使用 0.3.0 新原生包验证

**测试包位于项目 `.local/apk/ai-motion-0.3.0-test.apk`，包含本地历史与电脑同步。** 已完成 arm64 原生构建、版本 / 权限 / 签名和 SQLite 动态库检查，没有实机连接验收。0.2.0 旧 APK 不包含同步功能，不要用旧包验收。

1. 手机与电脑连接同一私人 Wi-Fi。
2. 电脑“设备与设置 → 开启局域网接收”。Windows 若提示防火墙权限，按实际网络环境允许私人网络访问。
3. 选择电脑的 Wi-Fi 网卡地址。复制配对链接，填入手机“连接电脑”。二维码携带相同链接；手机系统扫码工具是否支持打开自定义链接需要实测，应用内扫码相机尚未实现。
4. 手机点击“连接并同步记录”，按需允许 Android 本地网络权限。
5. 手机上运行 Motion Catch 模拟体验，电脑会收到计时、命中次数、暂停 / 结束及输入状态。当前同步不包含视频或真实骨骼。
6. 断线时手机继续保存最新阶段与已结束记录；连接恢复后重传，电脑按会话 ID 和序号去重。手机在后台关闭连接，回到前台后重连。

配对凭据仅在应用内存保留，有效期 12 小时。重启电脑或关闭局域网接收后需重新配对；手机重启后也需重新填写配对链接。手机训练历史存 SQLite，退出应用后保留。关闭接收会撤销现有连接。

局域网 WebSocket 使用明文传输，配对链接具有访问权限，只在可信私人网络使用，不对公网开放或配置端口转发。手机地址校验仅接受私有 IPv4 / 回环地址，不接受公网域名。网页来源连接会被拒绝。访客 Wi-Fi 隔离、VPN 网卡和防火墙可能影响连接。

## AI 接口

填写兼容 `chat/completions` 的**基础地址**（如 `https://服务地址/v1`）、模型名称和 API 密钥。不要把 `/chat/completions` 重复写进基础地址。

本机模型可以使用 `http://127.0.0.1:端口/v1`，密钥按服务要求填写；本项目没有自动安装大模型或假设电脑显存足够。远程地址要求 HTTPS。模型并非由本项目托管。

“测试已保存的接口”请求 `GET /models`，检查地址及授权是否可访问；部分服务不支持此接口，不代表模型必定不可用。“发送摘要并分析”才会请求指定模型。请求超时、授权失败、异常格式和过大响应均会停止并显示错误。

只在主动点击时发送：活动名称、来源、计时时长、次数、输入状态、置信度、本地结论。不会发送摄像头图像、视频、体重、设备 ID、会话 ID 或训练日期。接口返回的文本按普通文本展示，持久保存在本地；再次查看记录可读取上次建议。

API 密钥使用 Electron safeStorage 通过系统能力加密，仅主进程可读取；界面只获得“是否保存”的状态。导出备份不包含密钥或配对凭据。换电脑后需要重新配置密钥。

当前摘要没有关节角度证据，AI 不能凭次数判断动作是否规范。真实视觉动作复核、图像选择与上传尚未实现。

## 数据与热量

电脑设置页显示实际数据库所在目录，文件名 `workbench.sqlite`，使用系统用户数据目录；移动程序目录不会自动搬走数据库。测试脚本使用独立临时目录，不修改用户实际记录。

备份包含计划、训练统计、已保存的 AI 分析和可选体重。导入先校验，再使用事务合并；已有同 ID 训练不覆盖，未完成的导入记录不能由新设备冒认接管。

热量函数已实现 `MET × 3.5 × 体重 kg / 200 × 运动分钟` 的总能量估算边界，但当前没有给游戏自动分配 MET，也没有把模拟次数当成运动量。没有已确认强度与必要信息时显示“暂不估算”。未来需增加明确的运动类型与强度选择，才启用真实记录热量。

## 从源码构建

Node.js 24+，pnpm 11.25.0。桌面工程独立锁文件，不改变手机依赖布局。

```powershell
cd apps/desktop
pnpm install --frozen-lockfile
# 若依赖管理器没有下载 Electron 二进制：
node node_modules/electron/install.js
pnpm build
pnpm start
pnpm test
pnpm package
```

生成目录：项目 `.local/desktop/AI Motion-win32-x64`。`pnpm package` 先类型检查和构建，再只将打包代码与许可证放进便携程序，不携带源码、开发依赖、密钥或数据库。

完整流程检查：`pnpm exec electron scripts/smoke.cjs`。便携程序启动检查：`node scripts/verify-package.mjs`。后者只在临时数据目录用回环调试端口验证，普通启动不开放调试端口。

手机原生包构建：安装 SDK、JDK 17 后，在根目录运行 `./scripts/build-android-test.ps1`；如需保持旧测试版签名，传入自己的 `-DebugKeystore`。本轮已找回 Codex MSIX 应用缓存内的既有 SDK，并修复环境脚本查找方式。新增 expo-sqlite 需要重新原生构建，不能只向 0.2.0 更新 JS。本轮延续内部包的 `-SkipNativeLint`，正式发布前仍需补齐原生 release lint。
