# 运动控制与 Motion Catch

2026-11-05：用户当前无法接入手机，本轮先实现独立运动 / 游戏逻辑与 React Native 模拟体验。不包含真实姿态模型接入。

## 实际数据链路

```text
手指拖动 / 左右按钮
  → simulatedPose（明确标记的合成 33 点数据）
  → BodyController（运动核心，与平台无关）
  → MotionInput（source=simulation）
  → Motion Catch 状态机
  → 游戏界面 / 结果页
```

未来模型适配层应输出相同 PoseFrame，使用 source=pose，不将具体 SDK 对象传入游戏。当前模拟模式不会打开摄像头，也不初始化模型。

## 坐标与有效性约定

- PoseFrame 的关键点是图像归一化坐标，统一时间戳以毫秒表示，与消费端使用同一单调时钟。原生相机时间单位需要在适配器转换，不能直接拿设备 timestamp 当毫秒。
- mapToPreview 按顺时针 0 / 90 / 180 / 270 度旋转，再做预览镜像，再处理居中 cover 裁剪或 contain 留边。返回目标视图归一化坐标；原生模型若已旋转图像，适配器应传 rotation=0，避免重复旋转。
- 缺少 visibility / presence 均视为置信度未知；两者都有时取较低值。NaN、越界与非法置信度拒绝使用。
- torsoCenter 独立函数支持三个躯干点降级，且必须同时保留肩与髋。当前 BodyController 的控制策略更严格：左右肩、髋、膝、踝均需可见（阈值 0.5），不完整人体停止控制。
- 未来时间、倒序、重复和超过 250ms 的输入拒绝使用。失去追踪会清空平滑历史；新会话需 reset。
- 预览变换后躯干中心被裁出视野时停止控制；有效光标限制在 0.06–0.94 内。平滑时间常数 80ms，0.003 的归一化死区过滤轻微抖动，时间步长决定平滑权重。

## 游戏规则

- 一轮活动时间 30 秒，暂停时间不计入；进入后台自动暂停，恢复前台后等待主动继续。
- 游戏只使用运动输入的 x，将光标 y 投影到中央轨道。完整 2D MotionInput 保留供其他小游戏复用。
- 同时只有一个目标，x 在 0.2–0.8、y=0.5。新目标与当前光标保持距离；随机数可注入测试，连续不合适时有确定性降级位置。
- 光标半径为练习场宽度的 0.025，目标半径为 0.05；碰撞按屏幕圆形距离计算，与界面一致。
- 每次命中 10 分，同一输入时间戳不能重复计分。到 30 秒边界先结束，再停止碰撞判断，结束后分数冻结。
- 输入丢失 / 半身 / 低置信度时清空控制光标，不沿用旧坐标，倒计时继续。暂停按钮可同时停止计时与计分。
- 有效输入时长按输入的有效时间区间累加，最多计至 250ms 过期，不把整个卡顿间隔当成有效识别。
- 结果包含分数、命中数、活动时长、有效输入时长及平均连续命中间隔；命中少于两次不计算平均间隔。重开清空上一轮全部状态，当前仅内存保存。
