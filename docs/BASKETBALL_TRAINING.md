# 0.4.0 篮球训练第一阶段

2026-11-12。按用户确认的“原地运球 → 固定机位投篮 → 投篮位置与动作分析”顺序，本轮完成第一阶段实验实现，不宣称达到 HomeCourt 准确率。

## 手机分区与入口

底部固定 **首页、训练、记录、我的**。训练库包含原地运球、运球模拟、本地视频检查和原有 Motion Catch；电脑连接与摄像头检查在“我的”。进入相机 / 游戏详情隐藏底栏，返回原分区。底栏使用系统安全区，大字体与手势条仍需真机验收。

手机包：`.local/apk/ai-motion-0.4.0-test.apk`。电脑也更新为 0.4.0，仍从根目录启动脚本打开。新球体来源与运球详情需要电脑 0.4.0，不能用旧电脑 0.3.0 验收。

最终手机包 50,935,434 字节，SHA-256：`CD2D3651790BA39F4890BA884CD4206859F15F5DC94C8578756E62F412FCC757`。已核对签名、版本 0.4.0 / versionCode 4、arm64-v8a、内置模型与许可；未含电话状态、麦克风、外部存储权限。

## 本轮能力及边界

- 前置相机预览、本地 CPU 球体检测、检测框和推理耗时。
- 30 秒运球估计、暂停 / 继续 / 结束 / 重开；后台暂停并关闭相机。
- 最长连续计数、节奏（次 / 分钟）和周期波动；手机本地保存并补传电脑。
- 左右目标：完成上下周期、球在要求的屏幕侧才命中，然后换侧；中间区域不计目标命中。
- 合成球轨迹模拟不打开相机、不计实际进度和热量。
- 主动选择本地视频，在手机解码识别前 30 秒，与手工数对照；不上传、不存成实际训练。
- 开发用轨迹工具：`node scripts/replay-dribble.ts observations.json`；输入 `{frames: BallFrame[], expectedReps?: number}`，输出统计与参考差值，不读取视频、不联网。

**还没有：投篮出手 / 进球计数、左右手身份、真实全身姿态、动作规范评分、投篮热区与热量依据。** 手机“投篮训练”只说明后续状态。

模型识别 COCO 的 `sports ball` 类别，不能仅凭类别区分篮球、足球等。适合单人、单球、固定机位、光线充足、慢至中等速度的初步验证。

计数依据完整下落、转向、回升周期。**没有地面接触检测；持球大幅上下晃动也可能误计。** 遮挡、多球、低置信度、位置 / 尺寸跳变和超过 250 ms 的输入间隔中断轨迹。普通丢球时停止计数，30 秒计时继续。

实验阈值：置信度 0.45、振幅至少图像高度 6%（随球框调整）、周期 180–1800 ms、相邻计数至少 220 ms。未经实际设备和运球数据校准。节奏至少两个连续计数后计算；波动至少三个连续周期后计算。暂停和丢失的等待时间不混入节奏。

左右目标是屏幕两侧，不代表哪只手；前置镜像在入口只处理一次。边界为归一化 x<0.42 / x>0.58。

## 原生实现与依赖

独立 Expo 本地模块 `apps/mobile/modules/ball-vision`：CameraX Preview / ImageAnalysis → RGBA Bitmap → 按相机旋转转正 → TensorFlow Lite CPU 检测 → 归一化球框 → TS 会话。原有 VisionCamera 页保留，两种页面按路由互斥挂载。

串行分析器、KEEP_ONLY_LATEST、最多约 15 Hz，不积压帧；ImageProxy 在 finally 释放。停止 / 离开 / 销毁使旧 generation 与 token 失效，在分析线程释放检测器。原生与 JS 时钟每次连接映射偏移，重复、倒序、未来和过期帧不参与计数。只向 JS 传球框和耗时，不传完整画面。

视频只接受本地 file / content URI，限制 60 秒 / 100 MB，最多处理前 30 秒（67 ms 抽样）。同一模块仅一个分析任务。离开页面丢弃结果，已开始的原生计算不会立刻取消；下一任务需等待。选择器复制视频到应用缓存，系统可回收，不修改原视频。

模型为 TensorFlow EfficientDet-Lite0 int8 v1，Apache-2.0。已通过 [官方模型目录](https://www.kaggle.com/models/tensorflow/efficientdet/TfLite/lite0-int8) 对应的 Kaggle API 核实 TensorFlow 条目、版本 1 与 licenseName。下载来自 [Google 模型存储](https://storage.googleapis.com/mediapipe-models/object_detector/efficientdet_lite0/int8/1/efficientdet_lite0.tflite)，SHA-256：`0720BF247BD76E6594EA28FA9C6F7C5242BE774818997DBBEFFC4DA460C723BB`。

模型构建时下载并校验，不提交二进制；完整 Apache 2.0 许可与来源随 APK 打包，未分发训练图片和录像。

实际 Android 依赖：`org.tensorflow:tensorflow-lite-task-vision:0.4.4`（Apache-2.0），CameraX 1.7.0-alpha03（与现有 VisionCamera 一致）。本环境获取尝试的 MediaPipe / 新 LiteRT 官方构件返回 404，改用 Maven Central 可实际获取的官方 CPU 任务库，没有使用随机镜像。

**兼容限制：旧任务库的 arm64 JNI ELF PT_LOAD 对齐实测为 4096，尚无原生 16 KB 对齐保证。** 16 KB 页面设备可能安装或加载失败；正式发布前需升级推理库或源码重编并验证。不要求用户修改手机页面大小。本包仅供内部实验。

Windows CMAKE_OBJECT_PATH_MAX=240 用于哈希缩短安全区组件对象路径；过小限制会使构建目录加文件名都放不下，不能推定越小越好。
